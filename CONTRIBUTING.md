# Contributing to AirportRTW89

Thank you for your interest in contributing to **AirportRTW89**! We welcome community contributions, bug reports, and hardware testing feedback.

---

## 🏗️ Architecture Overview

AirportRTW89 consists of three core layers:

1. **macOS IOKit / Skywalk Layer (C++)**
   - Located in `AirportRTW/` and `include/`.
   - Interfaces with Apple's `IO80211Controller`, `IOSkywalkFamily`, and `IONetworkInterface`.
   - Implements IOCTL dispatch, frame encapsulation/decapsulation, power management, and scan results conversion.

2. **Network Protocol Stack (C / C++)**
   - Located in `rtw80211/`.
   - Adapted from OpenBSD `net80211` with macOS kernel compatibility shims.
   - Manages state machines (INIT -> SCAN -> AUTH -> ASSOC -> RUN), WPA/RSN handshakes, key negotiation, and A-MPDU session state (ADDBA).

3. **Realtek Hardware Core Layer (C)**
   - Located in `rtw/hal_rtw89/`.
   - Directly derived from Linux kernel `drivers/net/wireless/realtek/rtw89/`.
   - Compiled separately into `librtw89_c.a` via `scripts/build_rtw89_c_archive.sh` during Xcode builds.

## 🛠️ Build & Verification Guidelines

### 1. Build Verification
Always verify builds from the terminal using `xcodebuild`:
```bash
xcodebuild -project AirportRTW.xcodeproj -target "AirportRTW-Ventura" -configuration Release build
```

### 2. Symbol Resolution Check (Crucial!)
Before pushing or distributing any build, check that there are no unresolved internal C symbols in the resulting binary. An unresolved symbol with value 0 causes OpenCore to reject kext injection (`OCAK: Symbol ... has 0-value`):

```bash
nm -g build/Release/Ventura/AirportRTW.kext/Contents/MacOS/AirportRTW | grep " U _rtw"
```
**Expected result**: Empty output (no undefined `_rtw` symbols).

### 3. C Archive Dependency Analysis (`alwaysOutOfDate`)
When modifying files in `rtw/` or `scripts/build_rtw89_c_archive.sh`, ensure that the build phase re-runs. The Xcode project targets are configured with `alwaysOutOfDate = 1`. Do not remove this attribute from `project.pbxproj`.

## 📝 Commit & PR Guidelines

1. **Commit Message Format**:
   - Use conventional commit style where possible: `feat(...)`, `fix(...)`, `perf(...)`, `refactor(...)`, `docs(...)`.
   - Provide concise but context-rich descriptions (e.g., `fix(panic): guard null bss pointer during airportd disassociate`).

2. **Cleanliness**:
   - Do not commit `.DS_Store`, `DerivedData/`, `build/`, `xcuserdata/`, or autogenerated `FwBinary.cpp` files.
   - Keep `.gitignore` intact.

3. **Testing Requirements**:
   - If introducing datapath changes, please provide test results or `ioreg -r -c AirportRTW` output confirming bidirectional TX/RX counts.
